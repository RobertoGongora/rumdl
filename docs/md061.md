# MD061 - Indent footnote continuation lines

## What this rule does

Ensures multi-line footnote definitions indent every continuation line by four spaces (or a tab) relative to the `[^id]:` marker so Markdown renderers keep the entire block inside the same footnote.

## Why this matters

- **Avoid false code blocks**: Unindented continuation lines are interpreted as code blocks by many linters and renderers.
- **Preserve readability**: Consistent indentation makes it clear which paragraphs belong to a footnote.
- **Standards compliance**: GitHub Flavored Markdown and MkDocs both require the four-space indent for multi-paragraph footnotes.
- **Cleaner diffs**: Automatic fixes keep indentation uniform and avoid manual spacing mistakes.

## Examples

### ✅ Correct

```markdown
Here is some text with a footnote.[^1]

[^1]: First paragraph of the footnote.
    Second paragraph stays attached to the footnote.

    Third paragraph (or lists, code, etc.) is also indented.
```

### ❌ Incorrect

```markdown
Here is some text with a footnote.[^1]

[^1]: First paragraph of the footnote.
  Second paragraph is missing the required indentation.
```

This formatting causes Markdown parsers to treat the second paragraph as normal body text or an indented code block, breaking the footnote.

### 🔧 Fixed

```markdown
Here is some text with a footnote.[^1]

[^1]: First paragraph of the footnote.
    Second paragraph is now indented correctly.
```

## Configuration

This rule has no configuration options.

## Automatic fixes

When enabled, this rule automatically adjusts the leading whitespace of offending lines so they are indented by the required four spaces (or the equivalent tab width) relative to the footnote definition.
